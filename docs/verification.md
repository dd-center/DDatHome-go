# 重写与验证记录

日期：2026-09-21。基线：Go 仓库 `6da1364abd65820d4058ed87985e7bdc83018f6e`、Node.js 仓库 `fd0342242608e10631c4a3e2fe9d2424feab30c9`，均已通过远端 HEAD 核对。调度协议同时对照 Cluster-center 的 `src/ws.ts`。

## 修复范围

| 原行为 | 重写后 |
| --- | --- |
| 首次连接失败 panic | 可取消的指数退避，附随机抖动 |
| 写入 `DDhttp` 后阻塞等待一个结果 | 对齐 Node 的 `DDDhttp`，分别处理任务、wait、query、广播 |
| HTTP 无总超时、无限制 ReadAll | 默认 10 秒总超时，2 MiB 解压后响应上限，有限并发 |
| WebSocket Read 可一直卡住 | 握手、写入、pong 和业务查询分别有截止时间 |
| 每次只 Read 100 KiB，消息可能不完整 | 使用完整 WebSocket 消息读取及 1 MiB 调度帧上限 |
| gzip reader 创建失败仍继续读取 | 由 net/http 管理 gzip，损坏/超大解压响应作为失败 |
| 旧任务可能跨重连生命周期 | 每个会话独立 context，重连前取消并等待全部工作结束 |
| 服务 Stop 不清理 | 取消 HTTP、查询、重试、直播及状态服务，等待退出 |
| 通过当前工作目录找配置 | 默认执行文件旁，安装服务保存绝对路径，覆盖 #9 |
| 无任务时难以分辨空闲或故障 | 每分钟日志、状态/健康接口，覆盖 #3 的可观测性问题 |
| 无直播采集 | Node 兼容事件和 token，zlib/Brotli，认证/心跳超时，独立房间重试 |

这是一次实现重写，保留 v1 配置字段及服务命令，不是逐行翻译 Node。对照版本中无界 HTTP、过期直播 token 等行为没有沿用。HTTP/API 限流如实上报并冷却，不通过反复重连规避调度。

环境：macOS ARM64，官方 Go 1.27.1；官方安装包 SHA256 已核对。

- `go test -race -count=1 ./...`：通过。
- `go vet ./...`：通过。
- 自动测试语句覆盖率：83.2%（未通过测试实际注册宿主机系统服务）。
- `govulncheck` v1.8.0：No vulnerabilities found。
- 30 秒直播解析器 fuzz：931,265 次输入执行，通过，未出现崩溃。
- 11 个目标交叉编译通过：Windows 386/AMD64/ARM64、macOS AMD64/ARM64、Linux 386/AMD64/ARMv7/ARM64/MIPS64/MIPS64LE。
- macOS ARM64 成品 `--version`、`--check-config` 实际运行通过。

两分钟本地加速故障注入（同时启用 race detector）：432 次连接、2,556 个有效模拟结果、440 个预期失败、455 个取消任务、863 条损坏消息被处理。测试进程 goroutine 峰值 18、停止后 6（启动基线 3，模拟 HTTP 服务器仍在运行）。断线会取消进行中的 HTTP，请求并发不超过配置值；无 race 报告。

这些数字来自同一测试进程中的本地模拟服务，不能当作生产内存/吞吐指标或数周无泄漏的证明。测试还覆盖真实 TLS 的本地直播模拟、过期 token 重新获取、认证拒绝、认证/心跳超时及坏房间不阻塞继续分配。

## 真实服务冒烟

实际运行编译出的 macOS ARM64 程序 60 秒，独立测试 UUID、`RoomLimit=0`。全程一次连接，`connected=true`、`ready=true`，服务端 `homes` 可见 Go 1.27.1、平台、版本和正确身份。收到一个真实任务，接口返回 HTTP 200 / API `-352`，程序记录失败并进入 60 秒冷却；服务端记录 `resolves=0`、`rejects=1`，与本地结果一致。SIGTERM 后正常退出，exit code 0。

这证明连接、身份上报、失败提交、冷却及进程停机路径正常，**没有证明当前网络下能成功采集 B 站数据**，也没有完成真实直播采集验收。没有发送聊天。

## 验证边界

工作站没有 Docker Engine；[首轮 CI](https://github.com/dd-center/DDatHome-go/actions/runs/35640486770) 已在 AMD64/ARM64 原生 runner 构建镜像，并通过非 root 执行、身份生成及持久化检查。其他系统的本地服务注册仍需目标机器验收；交叉编译通过不等于在全部操作系统执行过。

真实 B 站接口的匿名访问、风控或鉴权变化不是客户端超时与重连修复所能解决。`valid` 仅表示本地 `code: 0` 并已写入 WebSocket；服务端 `homes` 的 `resolves` 才能提供接收端证据。历史服务会把“房间已加密”某些错误转换为成功，因此其计数不一定等于本地 `valid`。

正式替换常驻实例前，保留原 UUID 并停止旧实例；观察 24–72 小时的成功计数、失败原因、重连次数、资源趋势和直播认证状态。无需为此连续发送聊天或增加采集量。
